# 1. 项目介绍

## 1.1 项目背景

海关数据处理链路中存在若干辅助能力（汇率、字典映射等）。爬虫已将全球货币汇率写入现有数据库，但缺少统一的后台管理系统来维护数据，也缺少稳定的对外查询 API。

本项目 **Custom Data Toolkit** 是一个后台管理系统，用于管理海关数据处理过程中的辅助工具能力。

## 1.2 项目目标

MVP 核心目标：

```text
管理端登录
→ 维护货币信息
→ 查看与维护全球汇率
→ 管理对外 API Key
→ 外部系统通过 API 查询汇率
```

产品目标：

- 为已入库的货币与汇率提供管理维护界面。
- 对外提供可鉴权的汇率查询 API。
- 建立符合公司 AI Coding / Spec 规范的工程与文档基线。
- 为后续「海关字典管理」预留扩展位（本轮不实现）。

MVP 成功标准：

- 管理员可登录后台并维护货币（增删改查）。
- 管理员可按货币、日期筛选查看汇率，并可维护汇率值与 `checked` 状态。
- 管理员可创建/停用对外 API Key。
- 外部调用方携带有效 API Key，可按货币 code + 单日或日期区间查询汇率。
- 应用可在本机连接 MySQL 完整运行（管理端 + 对外 API）。

# 2. 用户分析

## 2.1 用户角色

### 管理员（Admin）

- 使用后台管理界面。
- 维护货币、汇率、API Key。
- 首版仅预置管理员账号，**不开放自助注册**。

### 外部调用方（API Consumer）

- 系统或服务，通过 HTTP + API Key 查询汇率。
- 不使用管理端 UI。

## 2.2 账号体系（MVP）

- 预置管理员：用户名 + 密码登录。
- 支持退出登录、修改密码（可选，建议实现）。
- 不包含：自助注册、多角色权限、Casdoor/Casbin、SSO。

# 3. 功能需求

## 3.1 货币管理

作为管理员，我希望在页面中查看、新增、编辑、删除货币信息，以便维护汇率关联的货币主数据。

验收标准：

- 列表展示货币名称与 code（字母码，如 `CNY`、`MYR_IM`；可为空的既有数据需兼容展示）。
- 可新增货币（name 必填；code 可选；若填则 MUST 为 1~10 位字母或下划线，规范化为大写且唯一）。
- 可编辑已有货币。
- 可删除货币；若仍存在关联汇率，MUST 拒绝删除并提示。
- 操作成功/失败有明确反馈。

## 3.2 汇率管理

作为管理员，我希望在页面中查看全球汇率，并在需要时维护汇率数据与核对状态。

验收标准：

- 可按货币、日期（单日或区间）筛选列表，支持分页。
- 列表展示汇率值（`data`）、日期、checked、创建/更新时间。
- 可新增或编辑某货币某日汇率（同一货币同一日期唯一）。
- 可更新 `checked` 标记。
- 爬虫入库数据与人工维护共用同一表结构。

## 3.3 对外汇率查询 API

作为外部系统，我希望通过 API 按货币 code 与日期条件查询汇率，以便业务系统消费汇率数据。

验收标准：

- 请求必须携带有效 API Key。
- 支持按 code + 单日查询。
- 支持按 code + 起止日期查询区间内记录。
- 无效 Key、缺失参数、无数据时返回明确错误或空列表（行为见 `api.md` / `spec.md`）。

## 3.4 API Key 管理

作为管理员，我希望创建与停用 API Key，以便控制对外访问。

验收标准：

- 可创建 Key（明文仅在创建时展示一次）。
- 可列表查看 Key 名称、状态、创建时间（不回显完整明文）。
- 可停用/启用 Key；停用后立即失效。

## 3.5 海关字典管理（占位）

本轮 **Out of Scope**。仅在文档与 OpenSpec 中保留占位。

已知方向（非正式需求）：后续可能用于将「货币名称」与 `code` 做标准映射；**具体字段与流程未定**，不得据此实现。需求明确后另开 OpenSpec change。

对外汇率 API 本轮只按 `code` 查询，不按名称查询。

# 4. 范围界定

## 4.1 In Scope（MVP）

- 管理端登录（预置管理员）。
- 货币 CRUD。
- 汇率列表查询与管理端维护（含 `checked`）。
- API Key 管理。
- 对外汇率查询 API（API Key 鉴权）。
- 工程文档、OpenSpec、AI Coding 基线。

## 4.2 Out of Scope（MVP）

- 海关字典管理业务实现。
- 爬虫本身的采集逻辑（假定数据已由外部写入 `rate` 表）。
- Casdoor / Casbin / SSO。
- 多租户、复杂 RBAC、审计日志导出。
- 公网生产级高可用部署（首版以本机/内网可运行为目标）。
- 汇率换算引擎、交叉汇率计算（仅存储与查询既有 `data`）。

# 5. 业务规则（摘要）

- `currency.code` 对外查询主键语义为货币字母码（应用层校验 `^[A-Z_]{1,10}$`，入库前规范化为大写；库列仍为 varchar(10)）；查询时 MUST 按 code 定位货币。
- `rate` 在 `(currency_id, date)` 上唯一。
- 管理端写操作 MUST 鉴权；对外查询 MUST 校验 API Key。
- 删除货币前 MUST 检查是否存在关联汇率。
- 海关字典相关接口与表本轮 MUST NOT 实现。

# 6. 成功指标

- 管理端可完成货币与汇率的日常维护闭环。
- 外部系统可用 API Key 稳定查询指定货币汇率。
- 文档与 Spec 足以驱动后续 AI Coding 切片，无需口头补充核心行为。
