# Custom Data Toolkit 功能规格说明书

> 状态：Product Spec Baseline（draft）  
> 目标版本：v0.1.0  
> 日期：2026-07-29  
> 上游文档：`requirements.md`  
> 本文定义可实现、可测试的业务行为，不定义具体代码结构。

## 1. 全局规则

### 1.1 时间与日期

- 业务时区固定为 `Asia/Shanghai`。
- 汇率业务日期使用 `YYYY-MM-DD`（对应表字段 `rate.date`）。
- 创建/更新时间使用带时区或统一约定的 datetime；对外 JSON 使用 ISO 8601。

### 1.2 文本处理

- 必填文本提交前去除首尾空白；去除后为空视为未填写。
- 用户输入按纯文本处理，展示时 MUST 防止脚本注入。

### 1.3 操作反馈

- 提交期间禁用重复提交。
- 成功/失败 MUST 有明确反馈。
- 删除货币等破坏性操作 MUST 二次确认。
- 服务端失败 MUST 显示面向用户的错误信息，不得展示内部堆栈。

### 1.4 鉴权分区

- **管理端 API**：Session Cookie + CSRF（写操作）。
- **对外公开查询 API**：`X-API-Key`，不使用 Session。
- 未登录访问管理端受保护资源 MUST 返回 401。
- 无效或停用的 API Key MUST 返回 401。

## 2. 管理端认证

### 2.1 登录

- 使用预置管理员的用户名与密码登录。
- 登录失败 MUST NOT 区分「用户不存在」与「密码错误」。
- 登录成功创建随机 Session ID，仅通过 HttpOnly Cookie 下发。
- 首版会话有效期固定 7 天。
- MVP MUST NOT 提供自助注册。

### 2.2 退出

- 退出只撤销当前会话。

### 2.3 修改密码

- 已登录管理员可修改密码。
- 修改成功后 SHOULD 撤销其他会话（当前会话可保留或全部重登，实现时在 `api.md` 写死一种并保持一致）。

### 2.4 当前用户

- 已登录可查询当前管理员基础信息（不含密码）。

## 3. 货币管理

### 3.1 列表

- 支持分页列表。
- 返回字段至少包含：`id`、`name`、`code`。

### 3.2 创建

输入：`name`（必填）、`code`（可选）。

规则：

- `name` 去除空白后非空，长度 ≤ 100。
- `code` 若提供：建议长度 ≤ 10；若非空则 SHOULD 在应用层保证唯一（库表无唯一索引时以应用校验为准，冲突返回 409）。
- 创建成功返回新建货币。

### 3.3 编辑

- 可更新 `name`、`code`。
- 目标不存在返回 404。
- `code` 冲突返回 409。

### 3.4 删除

- 若存在任意关联 `rate` 行，MUST 拒绝删除并返回 409（或 400，契约以 `api.md` 为准，全项目统一）。
- 无关联汇率时可删除。
- 删除前 UI MUST 二次确认。

## 4. 汇率管理

### 4.1 语义

- `rate.data`：汇率值，按既有库以字符串存储与传输。
- `rate.date`：汇率业务日。
- `rate.checked`：是否已核对（布尔）。
- `rate.currency_id`：外键指向 `currency.id`。
- 同一 `currency_id` + `date` MUST 唯一。

### 4.2 列表（管理端）

筛选（均可选，但至少一种合理默认）：

- `currencyId` 或 `code`
- `date`（单日）或 `dateFrom` + `dateTo`（闭区间）
- `checked`（可选）

规则：

- 支持分页与按日期倒序（默认）。
- 返回关联货币的 `code`/`name` 便于展示。

### 4.3 创建 / 更新（管理端）

- 允许管理员手工维护 `data` 与 `checked`。
- 创建时 MUST 指定货币与日期；同一货币同日已存在则 409，或提供 upsert 语义（MVP 采用：**显式创建遇冲突 409；更新走独立更新接口**）。
- 更新可修改 `data`、`checked`；不可改变导致唯一键冲突的 `currency_id`+`date` 组合（若允许改日期/货币，冲突时 409）。

### 4.4 删除（管理端）

- MVP SHOULD 支持按 id 删除单条汇率；删除前 UI 二次确认。

## 5. API Key 管理

### 5.1 创建

- 输入：`name`（必填，用于辨识）。
- 系统生成高熵随机 Key；**明文仅在创建响应中返回一次**。
- 服务端只持久化 Key 的安全哈希与元数据。

### 5.2 列表

- 返回 id、name、enabled、createdAt 等；MUST NOT 返回完整明文 Key。
- 可展示 Key 前缀（可选，便于辨认）。

### 5.3 启用 / 停用

- 停用后，使用该 Key 的对外请求立即 401。
- 可再次启用。

### 5.4 删除

- MVP MAY 支持删除；删除后不可恢复。若实现删除，行为与停用一样使 Key 立即失效。

## 6. 对外汇率查询

### 6.1 鉴权

- 请求头：`X-API-Key: <plain-key>`
- 缺失、错误、已停用 → 401

### 6.2 查询

参数：

- `code`：货币三位码（必填）。MUST NOT 接受货币名称作为查询键。
- 二选一时间条件：
  - `date`：单日
  - `dateFrom` + `dateTo`：闭区间（`dateFrom` ≤ `dateTo`）

规则：

- `code` 对应货币不存在 → 404
- 时间条件缺失或不合法 → 422
- 无匹配汇率 → 200 + 空列表（**MVP 统一：200 + `items`**）
- 成功返回汇率列表（至少含 date、data、checked、currencyCode）

### 6.3 禁止

- 对外 API MUST NOT 提供货币/汇率的写操作。
- 对外 API MUST NOT 使用管理端 Session 作为鉴权方式。
- 对外 API MUST NOT 按货币 `name` 查询（管理端可用 `q` 搜名称；名称↔code 由后续字典承接）。

## 7. 海关字典管理

本领域本轮 **无行为需求**。详见 `openspec/specs/customs-dict/spec.md` 占位。

MUST NOT 在 MVP 中实现字典相关页面、表或 API。

## 8. 验证清单（摘要）

- [ ] 未登录无法访问管理写接口
- [ ] 预置管理员可登录/退出
- [ ] 货币 CRUD 与有汇率时禁止删除
- [ ] 汇率唯一约束冲突返回明确错误
- [ ] 管理端可改 `data`/`checked`
- [ ] API Key 明文只出现一次；停用立即生效
- [ ] 对外查询支持单日与区间；无 Key 被拒绝
- [ ] 无字典相关实现混入 MVP
