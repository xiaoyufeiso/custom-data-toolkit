# Proposal: 管理页面内批量删除与 API Key 筛选

## Status

**Proposed（货币/汇率批量删除已完成；API Key 筛选与批量删除搁置）**

## Intent

货币、汇率和 API Key 页面当前只能在操作列逐条删除，无法先筛选、勾选并批量处理。API Key 页面也缺少名称和状态筛选。

本变更为三个管理列表增加当前页行选择和原子批量删除，并把删除操作统一移动到页面顶部；同时恢复 API Key 名称/状态筛选，使管理员能先缩小结果范围再执行页内批量操作。

## Scope

In Scope:

- 货币、汇率、API Key 三个管理页面使用 BizTable 行选择
- 支持点选和全选当前分页，单批最多 100 条
- 页面顶部显示“删除选中项（N）”，未选择时禁用
- 删除前使用 tendata-ui 确认交互明确数量和不可撤销风险
- 删除入口移出操作列；编辑、启停等非删除操作保留
- 新增三个 Session + CSRF 保护的原子批量删除 API
- 货币批量删除继续执行“有关联汇率禁止删除”
- API Key 支持名称包含匹配和启用状态筛选
- 保留现有单条删除 API，避免破坏兼容性

Out of Scope:

- 跨分页全选或按筛选条件删除全部结果
- 级联删除货币及其汇率
- 操作记录、撤销、重做和软删除
- 修改现有单条删除 API 语义
- 数据库表结构或外部 `currency` / `rate` 列语义变更
- 新增角色、权限或公开写接口
- 货币/汇率筛选能力的其它增强

## Expected Outcomes

- 管理员可在当前页选择 1～100 条记录并一次确认删除。
- 任一记录不存在或不满足业务约束时整批不产生删除。
- 筛选、分页、刷新不会把旧页面的选择误带入新结果。
- API Key 可按名称和状态组合筛选后再做当前页批量操作。
- 三页删除交互符合 tendata-ui/BizTable 和现有鉴权规范。

## Impact

- 前端：三个管理 view、service、locale 和组件测试。
- 后端：currency/rate/api-key 的 router、schema、service、repository 和集成测试。
- API：新增三个批量删除端点；扩展 API Key 列表查询参数。
- 文档：实现时更新 `docs/api.md`，完成后合并领域/UI Spec。
- 数据库：无迁移。

## Risks

- 批量删除不可撤销，误操作影响显著，尤其会立即使 API Key 失效。
- 爬虫或其他管理员并发写入可能让选中记录在确认前发生变化。
- 货币关联汇率检查若逐条执行会产生 N+1，必须批量校验。
- 前端循环调用单条 DELETE 无法保证原子性，禁止作为正式实现。
- API Key UI 与 `standardize-admin-ui-components` 切片 4 重叠，必须协调实施以避免重复改造。
