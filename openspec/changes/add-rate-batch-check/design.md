# Design: 汇率批量核对与列表操作分区

## API

新增管理端写接口：

```text
POST /api/v1/rates/batch-check
```

请求：

```json
{ "ids": [1, 2, 3] }
```

- 复用统一批量 ID 契约：1～100 个唯一正整数。
- 要求有效 Session Cookie 和 `X-CSRF-Token`。
- 成功返回 `204 No Content`。
- 任一 ID 不存在时返回 `409 BatchCheck.StaleSelection`，`details.missingIds` 标识缺失 ID，且不更新任何记录。
- 已核对记录幂等保持不变；仅把未核对记录更新为 `checked=true` 并刷新其 `update_time`。
- 保留现有单条更新和批量删除接口。

## Transaction

- Repository 使用单次 `IN` 查询并锁定选中汇率。
- Service 在写入前比较请求 ID 与查询结果。
- 全部 ID 有效后，仅更新未核对记录并提交一次。
- 任一校验或数据库错误回滚整个事务。

## Frontend Layout

页面顺序：

```text
页面标题 / 新建汇率
筛选与批量操作白色模块
  筛选条件
  批量操作
汇率表格
```

### 筛选条件

- 位于筛选与批量操作共用的白色容器上部，标题为“筛选条件”。
- 包含 code、日期、状态筛选，以及“筛选”“重置”按钮。
- 重置恢复全部日期、全部状态、默认排序和空 code，并回到第 1 页。
- 仅改变列表查询条件，不放置依赖行选择的操作。

### 批量操作

- 位于同一白色容器的筛选条件下方，标题为“批量操作”。
- 区域始终显示，避免选中行后页面跳动。
- 提供“全选本页”，并在旁边显示“已选择 N 项”。
- 操作顺序为“批量核对”和“批量删除”，按钮本身不重复显示数量。
- 批量核对未选择时为灰色禁用态，选择后使用公司组件 `type="secondary"` 蓝字蓝边白底按钮；批量删除使用危险按钮。
- 无选择时两个按钮均禁用。
- 页面标题右侧只保留带公司加号图标的“新建汇率”主按钮。

## Interaction

- 选择范围继续限定为筛选结果的当前页。
- 批量核对使用居中的 tendata-ui `Modal.confirm`，图标和颜色使用组件默认值。
- 确认后调用接口；取消时不发送写请求。
- 成功后清空选择并刷新当前有效页。
- 过期选择错误清空选择并刷新；其他失败保留选择并显示服务端用户消息。
- 所有新增文案使用 `react-intl`。

## Testing

- 后端覆盖成功、幂等、空/重复/超限/非法 ID、缺失 ID、未登录、CSRF 和单次提交。
- 前端覆盖区域分离、常驻禁用态、选择计数、确认/取消、成功、过期选择和筛选重置。
- 回归筛选、排序、分页、批量删除、新建/编辑和公开查询。
