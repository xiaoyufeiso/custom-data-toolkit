# UI 交互

## 设计语言

- 形态：后台管理系统
  - **顶栏**：产品名 + 语言切换 +（预留）用户信息区；不放业务菜单
  - **左侧栏**：业务功能入口（货币 / 后续汇率、API Key 等），由路由 `meta.menu` 派生
  - **内容区**：当前路由页面
- 登录等 `meta.public` 页：隐藏侧栏，仅保留顶栏
- 组件库：优先 tendata-ui（随 Tendata/公司前端模板）
- 反馈：操作成功/失败 Toast 或等价提示；删除需确认

## 页面流程

1. `/login` → 登录成功 → `/`（或 `/currencies`）
2. 侧栏：货币管理 / 汇率管理 / API Key → 对应列表页
3. 列表页 → 新建/编辑抽屉或弹窗 → 提交回列表
4. API Key 创建成功 → 一次性展示明文（可复制）→ 关闭后不可再查看

## 核心页面交互规则

### 登录页
- 用户名、密码；无注册入口
- 错误信息不区分用户是否存在

### 货币列表
- 分页；支持按名称/code 搜索（若实现 `q`）
- 删除有关联汇率时展示服务端错误，不静默失败

### 汇率列表
- 筛选：货币、日期或区间、可选 checked
- 支持新建/编辑 `data` 与 `checked`
- **新建汇率**货币选择：自定义下拉；选项文案 `code (name)`（无 code 仅名称）；按 `code` 首字母分组；无 code 归 `#`；右侧仅展示有数据的字母索引，点击滚动到对应段；列表可隐藏滚动条但仍支持滚轮；选项通过既有分页 API 串行拉全量（见 change `improve-rate-create-currency-picker`）

### API Key 列表
- 展示 name、prefix、enabled、创建时间
- 启用/停用切换；创建后明文仅弹窗一次

## 通用交互规范

- 表单提交后 MUST 显示成功/失败反馈
- 删除操作 MUST 二次确认
- 列表页 SHOULD 支持分页
- 加载中 MUST 显示 loading
- 未登录访问管理页 MUST 跳转登录

## 响应式要求

- MVP 以桌面后台为主；不强制移动端完整适配

## 可访问性

- SHOULD：关键按钮具备可辨识文本；表单 label 完整
