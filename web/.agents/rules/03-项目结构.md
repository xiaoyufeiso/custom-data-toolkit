# 03 项目结构

## 推荐项目结构，当新增或修改页面时，请参考此结构

```text
public/
src/
├── pages/                       # 路由级页面入口（页面壳）
│   ├── home/                    # 首页入口页
│   └── about/                   # 关于页入口
│
├── views/                       # 页面视图（与页面入口一一对应）
│   ├── home/
│   │   ├── services/            # 首页相关接口
│   │   ├── components/          # 首页业务组件
│   │   ├── hooks/               # 首页业务 hooks
│   │   ├── constants/           # 首页常量定义
│   │   └── utils/               # 首页工具函数
│   │   └── types/               # 首页类型定义
│   └── about/                   # 详情页业务模块
|             
├── shared/                      # 跨业务稳定复用层
│   ├── services/                # 通用接口
│   ├── components/              # 通用组件
│   ├── hooks/                   # 通用 hooks
│   ├── utils/                   # 通用工具函数
│   ├── constants/               # 公共常量
│   └── types/                   # 公共类型定义
│
├── store/                       # 全局本地状态
├── test/                        # 测试基础设施（setup、render、msw、fixtures）
├── locales/                     # 国际化文案
|   ├── index.ts                     # 语言注册入口
|   ├── en/                          # 英文资源（按模块拆分）
|   └── zh_CN/                       # 中文资源（按模块拆分）
|
└── assets/                      # 静态资源
├── router/                      # 路由配置
├── config/                      # 全局配置（环境变量、常量）
├── styles/                      # 全局样式
├── app.tsx                      # 应用入口
├── main.tsx                     # 主入口
```

## 目录职责

| 目录 | 职责 | 说明 |
|------|------|------|
| `router/` | 路由配置 | 集中定义路由表，统一懒加载 |
| `pages/` | 路由入口页 | 每个页面一个目录，仅做路由壳转发到 views |
| `views/` | 页面视图 | 与 pages 一一对应，存放页面的业务实现 |
| `shared/` | 跨业务复用层 | 通用组件、工具、hooks、类型等 |
| `shared/components/` | 通用 UI 组件 | 跨页面复用的基础组件 |
| `shared/services/` | 请求层 | 统一 API 封装和接口定义 |
| `shared/utils/` | 工具函数 | 通用工具（请求实例、格式化等） |
| `shared/hooks/` | 通用 hooks | 跨页面复用的 hooks |
| `shared/constants/` | 公共常量 | 跨业务共享常量 |
| `shared/types/` | 公共类型 | 跨业务共享类型定义 |
| `store/` | 全局状态 | Zustand store，管理本地 UI 状态 |
| `test/` | 测试基础设施 | 测试公共 setup、render 工具、MSW、fixtures、test helpers |
| `locales/` | 国际化 | 按语言和模块拆分的 i18n 资源 |
| `config/` | 全局配置 | 环境变量、常量、配置项 |
| `styles/` | 全局样式 | 全局 Less 变量和基础样式 |
| `assets/` | 静态资源 | 图片、SVG 等 |

## 强制约束

- `pages` 仅做路由壳，转发到 `views` 中的页面实现，不堆任何业务逻辑
- 业务实现统一放 `views/` 对应页面目录下
- 跨业务复用的代码统一放 `shared/` 下
- 接口定义：业务专属接口放 `views/xxx/services/`，通用接口放 `shared/services/`
- 类型文件放对应目录的 `types/` 下
- 查询参数转换放独立工具文件
- 通用组件放 `shared/components/`，业务组件就近放在 views 页面目录中
- 测试基础设施统一放 `src/test/`，例如 `setup`、公共 `render`、MSW、fixtures
- 单元测试与组件测试默认与被测文件就近放置，命名为 `*.test.ts` / `*.test.tsx`
- 不在 `src` 下新建独立的全局 `unit-tests/`、`specs/` 等顶层目录
- 新增页面必须在 `router/index.tsx` 中注册路由
- 国际化资源按模块拆分，不在单个文件中堆所有翻译

## 新增业务功能推荐结构

当业务逻辑较复杂时，建议在页面视图目录下按职责拆分，以下为视图下某页面的目录结构：

```text
views/tradeSearch/
  index.tsx                  # 页面入口，只做组装
  index.test.tsx             # 页面组件测试（就近放置）
  index.module.less          # 页面样式
  services/                  # 页面私有接口
    index.ts
    index.test.ts            # 服务层/接口适配测试（就近放置）
  components/                # 页面私有业务组件
    searchForm.tsx
    searchForm.test.tsx
    tradeTable/              # 目录结构与tradeSearch一致
  hooks/                     # 页面业务 hooks
    useTradeSearch.ts
    useTradeSearch.test.ts
  types/                     # 类型定义
    index.ts
  utils/                     # 业务工具函数
    index.ts
    index.test.ts
  constants/                 # 常量定义
    index.ts

src/test/
  setup.ts                   # Vitest 全局 setup
  utils/
    render.tsx               # RTL 公共 render 封装
  msw/
    server.ts                # MSW server
    handlers.ts              # 通用 handlers
```

## 约束案例

### ✅ 正确：新增页面的标准流程

```text
1. 在 views/ 下新建页面视图目录（如 views/tradeSearch/）
2. 在 pages/ 下新建路由壳（如 pages/tradeSearch/index.tsx），转发到 views
3. 在 router/index.tsx 中添加懒加载路由
4. 页面视图只做组装，复杂逻辑拆到 hooks/、utils/
5. 如需国际化，在 locales/zh_CN/ 和 locales/en/ 下新增对应模块文件
6. 如需测试，优先将测试文件就近放在被测模块旁；公共测试能力放 `src/test/`
```

### ✅ 正确：页面组件只做组装

```tsx
// pages/tradeSearch/index.tsx — 路由壳
import TradeSearch from '@/views/tradeSearch';

export default TradeSearch;
```

```tsx
// views/tradeSearch/index.tsx — 业务实现
import { SearchForm } from './components/searchForm';
import { TradeTable } from './components/tradeTable';
import { useTradeSearch } from './hooks/useTradeSearch';
import styles from './index.module.less';

const TradeSearchPage: React.FC = () => {
  const { data, loading, onSearch } = useTradeSearch();

  return (
    <div className={styles.page}>
      <SearchForm onSubmit={onSearch} />
      <TradeTable data={data} loading={loading} />
    </div>
  );
};

export default TradeSearchPage;
```

### ❌ 错误：所有逻辑堆在页面组件中

```text
pages/
  trade-search/
    index.tsx              # 页面 + 接口 + 状态 + 转换逻辑全部堆在一起
    index.module.less
```

### ❌ 错误：随意新建顶层目录

```text
src/
  trade-module/              # 不应在 src 下随意新增顶层目录
    search.tsx
    api.ts
```

### ✅ 正确：通用组件放 shared/components/

```text
src/
  shared/
    components/
      pageHeader/            # 通用页头组件
        index.tsx
        index.module.less
      emptyState/            # 通用空态组件
        index.tsx
```

### ✅ 正确：测试文件就近放置，测试基础设施集中放置

```text
src/
  shared/
    utils/
      request/
        index.ts
        index.test.ts
  views/
    home/
      index.tsx
      index.test.tsx
  store/
    useCounterStore.ts
    useCounterStore.test.ts
  test/
    setup.ts
    utils/render.tsx
    msw/server.ts
```

### ❌ 错误：把所有测试统一堆到独立顶层目录

```text
src/
  tests/
    views-home.test.tsx
    request.test.ts
    useCounterStore.test.ts
```

风险：测试与实现距离过远，模块迁移和重构时容易漏改、漏删、漏找。

## 典型判断规则

| 判断问题 | 放置位置 |
| --- | --- |
| 路由入口 | `pages` |
| 当前业务域能力 | `views` |
| 跨业务复用能力 | `shared` |
| 全局本地状态 | `store` |
| 测试基础设施 | `test` |
| 模块私有单测 / 组件测试 | 被测文件同目录 |
| 文案资源 | `locales` |
| 静态资源 | `assets` |
