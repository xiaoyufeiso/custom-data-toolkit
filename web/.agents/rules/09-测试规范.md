# 09 测试规范

## 测试目标

测试优先覆盖高价值和高风险逻辑，而不是追求形式上的覆盖率。

## 优先覆盖内容

- 参数转换函数
- 数据转换函数
- 复杂 hooks
- 权限判断逻辑
- 核心查询流程

## 建议工具

| 类型 | 工具 |
|------|------|
| 单元测试 | `Vitest` |
| 组件测试 | `React Testing Library` |

## 目录与命名标准

### 默认规则

- 单元测试、组件测试默认与被测文件就近放置
- 测试文件命名统一使用 `*.test.ts`、`*.test.tsx`
- 测试基础设施统一放在 `src/test/`
- `src/test/` 只放公共能力，不放某个业务模块的私有测试实现

### 推荐目录

```text
src/
  shared/
    utils/
      request/
        index.ts
        index.test.ts
  views/
    home/
      index.tsx
      index.test.tsx
    tradeSearch/
      hooks/
        useTradeSearch.ts
        useTradeSearch.test.ts
      utils/
        buildParams.ts
        buildParams.test.ts
  store/
    useLocaleStore.ts
    useLocaleStore.test.ts
  test/
    setup.ts
    utils/render.tsx
    msw/server.ts
    msw/handlers.ts
```

### `src/test/` 放置范围

- `setup.ts`
- RTL 公共 `render` 封装
- MSW `server`、通用 `handlers`
- 通用 fixtures、mock builders、test helpers

### 不推荐做法

- 把所有 `*.test.ts` 统一堆到 `src/tests/`
- 在每个业务目录下额外套一层 `__tests__/`
- 把测试工具函数散落到 `shared/utils/`，与业务代码混在一起

### 例外说明

- 若某个模块测试文件数量很多，可在该模块下新建 `tests/` 子目录，但仍应与模块同域
- 历史目录若已大量使用 `__tests__/`，可渐进迁移，不要求一次性全量调整
- 快照、fixtures、mock data 应优先跟随所属模块放置；只有跨模块复用时才提取到 `src/test/`

## 当前要求

- 新增复杂工具函数时，优先补单测
- 新增关键业务流程时，优先补核心链路测试
- 未覆盖测试时，至少在 PR 或文档中说明风险点

## 约束案例

### ✅ 正确：为参数转换函数补充单测

```ts
// views/tradeSearch/utils/buildParams.test.ts
import { describe, it, expect } from 'vitest';
import { buildTradeSearchParams } from '../buildParams';

describe('buildTradeSearchParams', () => {
  it('应正确转换表单值为接口参数', () => {
    const formValues = {
      keyword: ' 电子产品 ',
      country: 'US',
      dateRange: ['2024-01-01', '2024-06-30'] as [string, string],
      current: 1,
      pageSize: 20,
    };

    const result = buildTradeSearchParams(formValues);

    expect(result.keyword).toBe('电子产品');
    expect(result.countryCode).toBe('US');
    expect(result.startDate).toBe('2024-01-01');
    expect(result.page).toBe(1);
  });

  it('国家为空时 countryCode 应为 undefined', () => {
    const formValues = {
      keyword: '',
      country: '',
      dateRange: ['2024-01-01', '2024-06-30'] as [string, string],
      current: 1,
      pageSize: 20,
    };

    const result = buildTradeSearchParams(formValues);
    expect(result.countryCode).toBeUndefined();
  });
});
```

### ❌ 错误：无测试、无风险说明

```text
新增了 buildTradeSearchParams 函数，包含多种边界条件处理
但没有任何单测覆盖，PR 中也没有说明风险点
```

### ❌ 错误：把模块私有测试放到全局目录

```text
src/tests/
  tradeSearch-buildParams.test.ts
```

问题：测试与业务目录脱节，重构 tradeSearch 时不易发现关联测试。

### ✅ 正确：PR 中标注未覆盖测试的风险

```markdown
## 风险说明
- `buildTradeSearchParams` 中日期范围校验逻辑暂未覆盖单测
- 边界场景：dateRange 为空数组时的降级处理需人工验证
```
