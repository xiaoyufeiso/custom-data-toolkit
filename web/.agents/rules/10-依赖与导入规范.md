## 依赖与导入规范

### 参考来源优先级

涉及内部组件库和工具库时，统一按以下顺序判断：

1. 官方文档站
2. 项目内已有稳定用法
3. 组件库或工具库源码仓库
4. 团队补充规则或模块说明

> 如果多个来源冲突，以"当前生效版本对应的官方文档和项目实际安装版本"为准。

### 包依赖声明原则

- 项目依赖必须在 `package.json` 中显式声明
- 不允许依赖"其他项目里正好有"来隐式使用
- 新增内部库依赖时，需要确认版本来源与兼容范围
- 新增依赖前优先确认现有能力是否已满足需求

### 组件库使用原则

| 库 | 定位 | 使用规则 |
|----|------|----------|
| `tendata-ui` | 品牌化 / 增强组件 | 表单、按钮、弹窗、表格优先查此库 |
| `tendata-biz-components 业务组件库` | 跨项目业务语义组件 | 已有成熟业务块优先复用 |
| `tendata-utils` | 通用工具函数 | 格式化、数据处理优先查此库 |

### 导入总原则

- 优先使用包的公开导出入口
- 非必要不使用深路径导入
- 同一项目内导入风格保持一致
- 导入路径应可预测、可搜索、可批量升级
- 默认禁止手写深路径导入（除非官方文档明确推荐或团队约定）

### AI Coding 约束

- AI 在生成导入语句前，应优先参考项目内已有写法
- 若项目中已有同类组件或工具函数的稳定导入方式，保持一致
- 无法确认导出方式时，不要臆测深路径
- 无法确认包名、导出名、导入方式时，应优先查文档或项目已有实现

### 版本与兼容性

- 内部库升级时，要确认是否与当前 `React 18`、`tendata-ui` 基线兼容
- 若 `tendata-ui`、`tendata-biz-components`、`tendata-utils` 之间存在联动版本关系，应在项目文档中显式记录
- 不允许在未确认兼容性的情况下直接升级内部库主版本

### Source Of Truth

| 内容 | 权威来源 |
|------|----------|
| 实际导入写法 | 项目当前安装版本和源码可用导出 |
| 版本选择 | 项目 `package.json` 和 lock 文件 |
| 特殊约束 | 本目录 Rules 和团队补充文档 |

### 约束案例

```ts
// ✅ 正确：统一导入风格，从公开入口导入
import { Button, Table, Form } from 'tendata-ui';
import BizTable from '@tendata-biz-components/biz-table';
import { formatDate, formatMoney, formatPercent } from 'tendata-utils';

// ❌ 错误：臆测深路径
import Button from 'tendata-ui/es/button';
import TdButton from 'tendata-ui/lib/components/TdButton';
import formatDate from 'tendata-utils/dist/format/date';
```

场景：需要一个日期格式化函数

2. 若没有，再查 dayjs 是否已在项目依赖中 → 有，使用 dayjs

// ✅ 正确：项目内保持一致的导入方式
// views/tradeSearch/utils/transform.ts
import { formatMoney } from 'tendata-utils';

// views/companyDetail/utils/format.ts
import { formatMoney } from 'tendata-utils'; // 同一写法

export function formatMoney(value: number): string {

}
